# 響應式規則

**手機不是縮小的桌機。** 同一份資料,兩種資訊佈局。

## 賽程樹(最難的一個)

16 人賽程樹約 1000 × 700px。塞進 375px 螢幕只有三種結果:看不清、要一直捏放大、或是縮到字看不見。三種都不能接受。

| | 做法 |
|---|---|
| **桌機 ≥ 1024px** | 完整樹狀圖,一眼看到全貌 |
| **平板 768–1023px** | 完整樹,可橫向捲動,黏住當前輪次的欄位標題 |
| **手機 < 768px** | **分輪檢視** —— 一次只顯示一輪,頂部有輪次切換器 |

分輪檢視的規格:
- 頂部橫向 chip:`第1輪 / 八強 / 準決賽 / 決賽`,當前輪高亮
- 每場比賽是一張全寬卡片,兩位選手上下排列,右側是賠率
- 預設落在「有事情正在發生的那一輪」,不是第 1 輪
- 卡片可點開看詳情(投票、加入投注單)
- 提供「我的賽程」篩選 —— 只看自己那條路徑

**不要**在手機上用捏放大的完整樹。那是把設計問題丟給使用者。

## 投注單

| | 做法 |
|---|---|
| 桌機 | 右側常駐 dock |
| 手機 | **底部 sheet**。收合狀態是一條 bar:`3 關 · 4.82× · 可拿 482`,點擊展開 |

理由很實際:拇指在螢幕下方。所有博弈類 app 都把注單放底部,不是因為好看。

必做:

```css
padding-bottom: calc(var(--space-4) + env(safe-area-inset-bottom));
```

沒有這行,iPhone 的 home indicator 會蓋住「送出注單」按鈕。

## 賽中商店

手機優先。理由:比賽進行中,選手拿的是手機,而且**商店隨時會被管理員關掉** —— 每一秒都算。

- 道具列表全寬,買的按鈕至少 44 × 44px
- 商店關閉時,狀態要用整條橫幅告知,不是只把按鈕變灰
- 餘額固定顯示在視野內,不要讓人捲上去看

## 管理介面

看起來像桌機優先,但有個現實:**辦活動的人是站在現場拿著手機的。**

所以「開始 / 重開 / 判定勝者」這三個操作**必須在手機上好按**:

- 這三顆按鈕在手機版要全寬、分行、間距夠大,避免誤觸
- 判定勝者要有二次確認 —— 誤按會直接結算所有注單
- 階段切換、建立賽程這類「坐著做」的操作,可以桌機優先

## 斷點策略

**版面用視窗斷點,元件用 container query。**

```css
/* 版面:少數幾個 */
@media (min-width: 768px)  { /* 平板以上 */ }
@media (min-width: 1024px) { /* 桌機以上 */ }

/* 元件:看自己容器有多寬,不看螢幕多寬 */
.match-card { container-type: inline-size; }
@container (min-width: 380px) {
  .match-card__odds { display: block; }
}
```

為什麼:同一張比賽卡可能出現在右側 dock(340px)、手機全寬(375px)、桌機主區(600px)。
它該依據**自己的容器**調整,不是依據螢幕。用視窗斷點會在 dock 裡出現「桌機螢幕但卡片很窄」的錯誤佈局。

## 品質底線(每個畫面都要過)

- [ ] 375px 寬:無橫向捲動、無溢位
- [ ] 所有可點擊目標 ≥ 44 × 44px
- [ ] 底部固定元素有 `env(safe-area-inset-bottom)`
- [ ] 橫向捲動區域有視覺提示(漸層遮罩或部分露出下一項)
- [ ] 鍵盤 focus 看得見
- [ ] 文字對比度過 WCAG AA
- [ ] 載入中、空、錯誤三種狀態在兩種尺寸都設計過
