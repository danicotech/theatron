# 賽事平台視覺規範

這個專案的視覺方向已經決定,**不要重新發想**。你的工作是套用,不是選擇。

## 四條硬規則

1. **元件只能用語意 slot(`--surface-*`、`--text-*`、`--accent-*`、`--state-*`)。**
   禁止一次性 hex 值,禁止直接引用原始色階。違反這條,活動換主題功能就死了。

2. **字體只有三個角色,不新增。**
   `Archivo` 標題 / `Noto Sans TC` 內文 / `IBM Plex Mono` 所有數字。
   賠率、代幣、倒數計時一律 mono + `font-variant-numeric: tabular-nums`,數字跳動時才不會左右晃。

3. **手機不是縮小的桌機。** 賽程樹在手機上是分輪檢視,不是可捏放大的完整樹。
   投注單在手機上是底部 sheet,不是右側 dock。細節見 `responsive.md`。

4. **產出任何畫面之前,先讀 `slop-review.md` 並自我檢查一遍。**
   通用化的視覺是這個專案明確要避免的失敗模式。

## 判準

一個元素是不是「AI 感」,不看它用了什麼顏色,看**它有沒有被選過**。
未經指定而落到預設值 → 是 tell。
有理由地選了一個顏色 → 就算是紫色也通過。

所以每個視覺決定都要能回答:「為什麼是這個,而不是預設的那個?」

## 靈感從哪裡來

不要從「什麼風格」開始,從主題自己的世界開始 —— 賠率表、記分板、籤位號碼牌、票根。
完整清單見 `vernacular.md`。

## 參考檔案

| 檔案 | 什麼時候讀 |
|---|---|
| `tokens.md` | 寫任何 CSS 之前 |
| `responsive.md` | 做任何版面、或改動賽程樹/投注單/商店時 |
| `theming.md` | 新增活動主題,或不確定某個值能不能自訂時 |
| `vernacular.md` | 設計新版面或新元件時 |
| `slop-review.md` | 產出畫面後、開 PR 前 |

## 元件邊界

`packages/ui` 是純展示層:**不 import API 型別、不呼叫 fetch、不知道賽事規則。**
它只收 props。業務邏輯留在 `services/web/features`。

這條是「後續各活動客製化」能成立的前提。
