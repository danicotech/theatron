# 觀局雅集：本機試玩操作手冊

## 入口與邊界

開啟 [觀局雅集](http://127.0.0.1:3000/sportsbook)，或首頁頁首「觀局雅集」。示範賽程 → 場次 → 比武 → 選手詳情／投注按鈕也會開啟同一個 React 中心，並標示所選玩家。

本版的帳號、Discord 身分、點數、管理與獎品都是同來源瀏覽器內的模擬。所有試玩者都能進入管理，不代表正式裁判授權。沒有購點、轉帳、提領、真實 OAuth 或寄送地址。正式 `/t/`、`/judge/` 及生成 API 不受本機帳本取代。

## 檢視／管理模式（2026-09-22）

匿名入口已停用，既有匿名會員與帳本保留，不自動轉入新會員。檢視模式可閱讀、查看賽程；報名、投票、投注與兌換使用註冊會員。每會員每盤一票，封盤前改投只替換該盤原票。

1. 管理模式 →「另開一屆試玩」→ 名單來源「開放會員報名（空白名單）」；填活動名稱、2–64 人上限，建立活動。
2. 管理區的「參賽者報名入口」帶入同屆 ID。會員到「我的參賽」閱讀完整規則並確認 → 填遊戲 ID、角色姓名 → 設定流派、武器、裝備、武學 → 最後確認完成報名。儲存草稿不占完成名額，也不能排入對局。
3. 「儲存並開啟完整備戰方案」先存報名草稿，再開既有配置器；完成後「帶回角色設定」，確認報名。配置器本機活動資料按會員與活動隔離；匯入文字只對應原會員。
4. 管理者在同一頁設定活動、查看報名資料，關閉報名後勾選已完成者，按前移鍵調整首輪順序，再確認發布。支援奇數輪空；4 人以上自動建立季軍戰。發布後固定名單，避免投注對象改變，需另開活動才能換人。
5. 發布自動連結會員與選手、產生賽程與盤口。會員「我的參賽」可查看自己的對局；首頁賽程 → 比武 → 點角色可看實際自填配置，再開觀局雅集。參賽者不能投注自己的場次或本屆名次盤，可投注其他場次。
6. 管理模式切換活動與對局 → 開賽封盤 → 逐局記勝者、秒數 → 儲存賽果草稿 → 檢查結算 → 確認派彩。已結算結果不能普通編輯改寫；重測另開活動。
7. 切回檢視模式檢查我的注單、點數紀錄与獎品兌換。模式切換只是本機介面分工，不是正式權限隔離。

帳號可透過登出／登入切換，以同一瀏覽器模擬多名報名者；資料共用 IndexedDB，登入身分是分頁 session。正式後端、跨裝置同步、裁判授權尚未接入。

## 第一次試玩

1. 「登入／註冊領 1,000 點」→「註冊」：帳號 3–32 位英數字、底線、點或連字號；密碼至少 8 字；暱稱最多 40 字。帳號不分大小寫。
2. 首次建立會員入帳 1,000 點。重新登入、刷新、開另一屆、綁定登入方式均不再贈點。
3. 也可選「Discord 模擬」輸入示範身分與暱稱。已登入會員可在「點數紀錄」綁定尚未使用的模擬身分，之後由同一身分登入原會員。兩個已有會員不自動合併。
4. 首頁開啟時可「以目前賽程建立試玩」：複製姓名與籤位，清除比分，從賽前開始。管理模式也可選擇預填 2–64 名示範選手，含奇數輪空；檢視模式不建立活動。
5. 建立前需要自訂姓名與籤位時，先到原賽程編輯，再由頁首匯入快照。試玩快照不隨原示範人數、拖曳換人或比分改動；需要另一份名單時另開一屆。

## 選盤與注單

- 場次盤：整場勝負、每局勝負、BO3 比分、每局時間、整場總時間。未定對手不開盤，輪空不開盤。
- 時間預設單局 90 秒、整場 180 秒。等於門檻算「以上」；整場只加總實際進行各局，排除等待時間。
- 名次盤：冠、亞、季、殿軍各自一盤，僅限單注。2–3 人不開季／殿軍盤；4 人以上另有季軍戰。
- 選擇賠率加入注單；預設「各盤單獨投注」，同場不同盤口可同時選擇，同盤換選項才取代舊選擇。切換「跨場串關／包牌」後，同場仍只能選一種玩法；包牌模式保留同玩法多選。不同場次最多 12 場，可複選過關數及開啟包牌；名次與其他玩法不混串。
- 每組本金為 10 點的正整數倍，整筆總本金須為 100–100,000 點且不得超過餘額。先「檢查注單」，再於摘要「確認」才扣點。摘要顯示每組金額、組合數、總本金、最高返還與最高淨損益；包牌不把互斥結果算成同時中獎。
- 確認期間若其他分頁改票、改賠率或封盤，返回已更新的注單要求重新確認。成立注單永久保留當時賠率。
- 桌機注單在右側；手機使用可展開底部面板。草稿按會員與賽事隔離；登出清空畫面，不顯示前一會員注單。

新盤預設管理者固定報價，成交後鎖定。預設不接受任何賠率變動，也可明確選擇只接受較高賠率。匿名與會員仍每盤一票，但固定報價不受人氣影響。舊人氣盤可按「本屆切換固定報價」保留現價並停止跟票變動；已成立票不變。原人氣參數僅保留為舊版試玩，不是官方開盤公式。時間門檻在首張相關注單後鎖定。

完整來源、規則及差異見 [台灣運彩串關對照](TW_PARLAY_RULES.md)。

## 裁判操作

1. 在首張注單前完成「會員與參賽者對應」：對應會員不能投自己場次，也不能投本屆名次。已開賽或已有注單後對應鎖定。
2. 管理 →「開始比賽」→ 確認：本場全部盤口封盤，本屆名次盤同步封盤；其他尚未開始場次仍可下注。
3. 「填寫逐局賽果」：每局選勝者並填實際整數秒。BO3 須產生兩勝；2:0 的第三局留「未進行」。儲存僅存草稿。
4. 「確認結算」會先列本次完成注單數與派彩／退款總點數；二次確認才在一筆資料庫交易內寫賽果、晉級、注單與帳本。
5. 未進行第三局的勝負／時間盤作廢。沒有秒數不能結算，不以假時間補足。決賽結算冠亞軍，季軍戰結算季殿軍；不互相假設結果。
6. 未結算盤口可填原因作廢。單注退本金；串關該關按 1.00 倍，所有剩餘關命中才派彩；全作廢退本金；某組內任何一關落敗，該組不派彩；其他命中的組合仍可得獎。全部組合可判定後一次結算，總額四捨五入至整點，最高 2,000 萬點。
7. 已結算結果鎖定，不能用一般賽程編輯／復原改寫。重測請另開一屆，保留舊注單與餘額。

由運彩中心進入比武會帶 `sportsEvent` 與 `match`。首頁以獨立快照呈現選手、比分、冠軍與季軍戰，保留紅藍卡面、金線與勝敗效果。此時原示範編輯器停用，應回運彩管理結算。

## 獎品兌換

預置三件明標「示範」獎品。管理可編輯名稱、說明、整數點數價格、可用庫存、上下架。

會員申請 → 確認後扣點並保留一件庫存 → 管理核准 → 管理標示已發放。會員只能取消自己的待審核申請；管理可取消待審核或已核准單，各退點／回補庫存一次。已發放不得倒退或再次退款。庫存不足、餘額不足、確認期間價格改變都不成立交易。

## 儲存與技術維護

- `web/src/features/sportsbook/`：獨立展示模型、純運算 engine、IndexedDB database、React UI、首頁 bridge。不是生成 API 契約。
- IndexedDB `lunjian-sportsbook-demo`，version 1，單一 `state/root` 聚合資料；每次命令在同一 `readwrite` 交易中重讀、驗證並寫入。只有 `oncomplete` 才回報成功；金額與千分賠率均以十進位字串儲存、`bigint` 運算。
- 每個命令保存 idempotency key + 內容簽章，重送不重扣／重派。結算確認含 revision，資料改動後須重新取得摘要。並行交易由 IndexedDB 序列化。
- 密碼採 Web Crypto PBKDF2-SHA256，210,000 次與每會員獨立隨機鹽，無明文保存。
- sessionStorage `lunjian-sportsbook-user` 是分頁登入狀態；localStorage `lunjian-sports-slip:<會員>:<賽事>` 只存草稿。會員、餘額、賽事、交易在 IndexedDB。
- BroadcastChannel `lunjian-sportsbook-demo` 同步帳本變更，回到分頁再讀取；最後訂閱卸載關閉通道。通知失敗不將已提交交易回報成失敗。
- 固定使用 `127.0.0.1:3000`；換 hostname／port 是另一份資料。清除網站資料會刪除本機試玩紀錄，沒有雲端帳戶復原。
- lab canonical `lunjian-layout.html` 增加 `lunjian:sports-open`、`lunjian:ready`，React 回傳 `lunjian:sports-select`，runtime `applySportsbookEvent` 接展示快照。卸載清除監聽；更新 lab 後執行既有生成器。

## 驗收狀態

自動化涵蓋贈點／綁定、帳號大小寫、鎖價、封盤與身份限制、IndexedDB 併發扣點、操作冪等、時間門檻、BO3／名次與季軍戰、串關作廢、獎品庫存競爭與退款、React 二次確認／失敗狀態、比武交接／焦點／清理。最新命令結果見 [UI_UX_VERIFICATION.md](UI_UX_VERIFICATION.md)。

CUA 瀏覽器工具本輪仍因執行環境啟動失敗而無法操作。375–1440px 真實畫面、手機底部面板、3D 同屏、真實鍵盤焦點圈限、多個實際瀏覽器分頁與背景節流仍待實機驗收；DOM／fake-indexeddb 測試不能代替。Hestia、真實 Discord OAuth、正式權限及獎品履約列下一階段。

## 注單即時賠率（2026-09-21）
不同場次各選一種玩法或比分後，注單直接顯示各關賠率相乘與總賠率，不必先輸入本金；手機收合列亦顯示單一組合的總賠率。跨場串關模式同場改選仍替換原玩法；各盤單獨投注則保留同場多盤，不相乘。包牌或多種過關數會顯示組合數，可展開查看每組算式，避免誤將互斥選項相乘。

## 各盤獨立投票與單注（2026-09-21 最新覆蓋）
- 每會員每個盤口一票，封盤前改投只替換該盤原票；同場整場勝負、BO3 比分、總時間、各局玩法可同時保留投票。
- 投注單預設「各盤單獨投注」，每盤可选一個結果，各筆套用所填本金，每筆至少 100 點、10 的倍數；確認列出總扣點。
- 一次確認原子建立多張獨立單注；每張各自鎖價、扣點、結算及退款。任一張失敗整批不成立，重送不重扣。單盤限串關、封盤、自投注限制仍由交易層驗證。
- 投注並非只能下一票；已成立的單注不會因改選或再次投注被取代，再次投注會另外扣點建單。
- 各筆返還合計是全部命中的估算；互相矛盾的結果不可能同時中獎，介面有明確說明。
- 跨場串關／包牌保留原規則，同場多類別不會被直接乘成串關。既有注單和帳本不遷移。

## 精簡注單流程
選盤後右側／手機底部只更新摘要。方式與本金在精簡注單內調整；「查看選項與設定」可移除選項、設定包牌／過關數及賠率政策。按「完成調整」返回摘要，再按「檢查注單」核對完整選項、總扣點及返還，最後確認才成立。


## 完整報名表（2026-09-29）
管理模式建立「開放會員報名」活動後，切檢視→我的參賽：
1. 阅读規則、勾選確認。
2. 填遊戲 ID、角色姓名、對戰經驗及可參賽時段；伺服器、Discord 選填，自評選待評估亦可。
3. 填流派、主副武器、裝備與武學；沒有攜帶者填「無」。可儲存後前往完整備戰方案，回到同一會員、同一活動。每項角色文字最多 4,000 字。備註選填。
4. 核對公開角色與聯絡／出席資料，各區可返回修改，最後按「確認完成報名」。成功後顯示報名編號與等待排賽狀態。

草稿可保留不完整內容，但需要遊戲 ID 和角色姓名；尚未確認不算報名。已完成者可在報名開放且未發布時修改。報名額滿／截止先顯示原因，不引導新會員填到最後才拒絕。聯絡與出席資料只在本機會員及管理表單顯示，不傳到首頁公開投影。

會員、活動與頁籤在送出期間停用；不可逆操作透過確認視窗，以按鈕文字明示扣點、發布、封盤、派彩或退款。失敗保留注單／表單，可修正後重試。

檢查注單若點數不足，原因顯示在本金與確認按鈕附近並取得焦點；修改本金後清除舊提示。完成下注會切換至「我的注單」，鍵盤焦點移至結果內容；取消確認則回原按鈕。桌機側欄過高時隨文件捲動，手機加選保持收合，按底部摘要才展開。實際三尺寸驗收與重跑腳本見 UI_INTERACTION_PLAN 的雅集段落。

發布對局後，參賽者在「我的參賽」按「查看我的對局」，會移到該場次內容。管理者可用「查看完整賽程」進首頁，姓名卡開公開角色配置，比分進比武；活動識別保持一致。自己的比賽及本屆名次盤標示「僅供觀局」並停用下注；其他場次仍可下注。原注單草稿若因會員對應改變而變成自己的對局，也會在扣點確認前說明限制，不扣點。

盤口在確認期間改價或封盤時，原扣點確認會關閉，注單內顯示更新原因與新摘要；請再次檢查，系統不會自動扣點。時間盤一旦已有注單，管理設定中的秒數門檻唯讀，避免改變已成交條件。管理設定錯誤會定位到表單內，修正後可重試；長視窗的標題與關閉鈕保持可用。


## 從首頁直接報名
首頁「報名」章按「開啟報名表」即可使用四步表單，無須先進管理頁或手動帶活動代號。首次點擊建立本機空白報名活動（64 人上限）；已有報名活動則沿用最近一屆，已截止不會自動重開。指定 sportsEvent 時仍以指定活動為準。表單依序為了解說明、會員登入／註冊與參賽資料、角色配置、確認報名；支援儲存草稿及完成後查看憑據。也可直接開 `/sportsbook?entry=registration`。所有資料留在同一瀏覽器；管理者在觀局雅集的管理模式調整活動、報名上限與籤位。


### 首頁書卷報名
首頁「報名」章點「展卷報名／展卷查看報名」，直接在原场景填寫四步表單；登入／註冊使用小視窗，完成後返回紙面。收卷會保留本次未儲存內容；離開頁面或刷新前請儲存草稿。完成後顯示已入冊憑據。這取代先前該章的大型報名視窗；直接備援網址仍為 `/sportsbook?entry=registration&event=活動代號`。


### 公開入口與管理入口（2026-09-29）
公開 `/sportsbook` 和比武觀局不再提供管理切換／示範建賽；管理由 `/sportsbook?mode=manage` 進入。首頁 `?mode=manage&preview=1` 可檢查演出與示範賽程編輯。此旗標僅控制本機展示，不是身分授權。一般會員入口為頁首會員專區，模擬 Discord 僅管理模式可見。規劃見 PUBLIC_PRESENTATION.md。
