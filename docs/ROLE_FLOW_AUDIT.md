# 三身分完整流程驗收

日期：2026-10-12。目標：從首頁報名到配裝、BP、投注、管理排賽、抽獎與頒獎的可操作流程。

## 執行方式

- 三個 agent 分別扮演報名者、觀眾與管理者，使用隔離 Chromium contexts；不寫入使用者現有瀏覽器資料。
- 以指定的 design-taste-frontend 做既有首頁視覺與入口審查；表單、投注與管理產品介面依專案 tournament-design-system，動態依 animation-systems。
- 設計取向：保留論劍紙墨及深夜賽事色系，重點是流程與狀態。功能介面 DESIGN_VARIANCE 3、MOTION_INTENSITY 3（抽籤與擲骰回饋 4）、VISUAL_DENSITY 5；不更換既有字體、Logo、章序。
- 本次可測範圍為本機 IndexedDB/localStorage 流程。管理模式有持續的本機模擬標示；沒有以本機帳號替代正式權限驗收。

## 分角色紀錄

- [報名者](PARTICIPANT_FLOW_AUDIT.md)：入場、已讀、註冊、資料、角色／裝備、報名、BP 與其他場投注。
- [觀眾](SPECTATOR_FLOW_AUDIT.md)：不同場次及冠軍下注、確認取消、餘額、封盤、結算、持久化。
- [管理者](MANAGER_FLOW_AUDIT.md)：籤位、盤口、場次管理、抽獎與頒獎。

## 獨立對局小工具

- 入口：首頁與 `/home` 的「更多 → 對局小工具」，以及觀局／會員中心的「對局小工具」。
- 擲骰：雙方稱呼、均勻隨機六面骰、擲骰動畫、點數比較、平手與重擲。使用 crypto rejection sampling 避免取餘數偏差。
- 猜拳：第一方選好即隱藏，顯示交接畫面；第二方確認接手後出拳，雙方一起揭曉，可重新開始。這是共用裝置的現場輔助工具。
- 不接收 tournament 或 command props，不讀寫賽事資料，不更動先後攻、場次狀態或賽果。關閉即清除本次工具結果。
- 動畫支援 reduced-motion；切換模式和卸載清除 timer；關閉視窗返回可見入口。
- 已以 1198／375px 驗證：擲骰、隱藏出拳、結果、無水平溢出、Escape／焦點、無 JS 錯誤；操作前後整份 IndexedDB 賽事 state 相同。
- 證據：`previews/role-audit/tools-results.json` 與 `tools-{dice,hands}-{1198,375}.png`。
- 重跑：`node scripts/verify-match-tools-browser.mjs`。

## 環境與規則界線

- 進行中場次依既有賽制封盤；可查詢當前場，仍開放的未來場可投注。全屆名次盤於首場開賽封盤。
- 目前沒有可用的 Hestia 開發後端。本次不宣稱正式登入、角色權限、跨裝置同步、多人同時操作或正式伺服器派彩已驗證。
- BP 以大會評段為準，不以報名自評代替；開賽後配置三局固定。人工拒絕／退款條件由裁判確認，不依文案猜測自動退款。
- 抽籤分組為現有單淘汰賽的首輪對局，包含輪空；尚非多人隊伍或循環小組賽。比賽時間是逐局實際秒數及整場加總，沒有自動判輸的倒數計時。

- 獨立工具 1198／375px：操作前後賽事資料相同，手機無水平溢出；另驗證 `/home` 375px 入口及 reduced-motion。
