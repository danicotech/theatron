# 武俠晉級樹：獨立席位與中央決賽

## 2026-09-21 最新設計

依使用者最後一張 NBA 晉級表與已同意的分析重構，取代舊「每場一顆雙人卡按鈕、左右不同底色」模型。桌機以整棵樹居中，左右最外側為初始選手，逐輪向中央決賽會合；中央以「左決賽名帖 — 冠軍 — 右決賽名帖」同一水平中線排列，比分在冠軍下方，季軍賽獨立位於下方。

- 一個席位一張原生按鈕名帖。左右採黑白對立卡面，可由示範管理列互換，姓名完整換行、段位／籤號／比分各自可讀；未開始比分為「—」。姓名字印是裝飾，不冒充未提供的玩家肖像。
- 每場的兩張名帖分開定位、由兩條折線匯合；匯合處是獨立的比分／場次按鈕。下一輪席位只顯示該席選手或前場勝者占位，沒有外層雙人卡。
- 已確認勝者：大幅傾斜勝章落印，亮黃色晉級線加上流動筆段。落敗：保留姓名與比分，背景由黑／白方過渡到暗紅墨黑，明示「落敗」，不降低整卡 opacity。懸停或鍵盤聚焦只突出同一玩家已知路徑。
- 只有決賽 done 且 winner 屬於雙方並能找到公開玩家時，才顯示冠軍。冠軍插畫 manga-champion 是象徵插畫，不是玩家肖像；未確定顯示「冠軍待定」。
- 128px 名帖、48px 連接區，中央另留 144px 冠軍與兩側 24px 間距；較窄視窗只在樹內捲動，初次置中，後續輪詢保留位置。長名稱增高時計算整體間距，不截字。
- 小於 768px 分輪檢視，名帖全寬；場次按鈕放在兩位選手下方，冠軍在決賽輪的兩位選手之間。Tab／方向鍵、焦點及觸控入口保留；reduced-motion／靜態閱讀停用落印、敗退與流動線動畫，仍完整顯示黑白方及勝敗。

## 操作

公開賽程：名帖 → 選手面板（留在賽程）→ 前往同場比武；或直接點比分／場次進 #duel。面板關閉還原名帖焦點，輪詢替換 DOM 後也能還原。比武中的角色、裝備資料、正式盤口及本地示範投注流程保留。

裁判總覽：使用相同 lab 樹的 React 適配器 WuxiaBracket。名帖、比分與冠軍入口均進入相應 /judge/[slug]/m/[matchId] 裁判台，不在公開卡片上寫入賽果。正式賽程有裁判台入口，驗證及權限沿用既有後端。

BO3：先選本回合勝者，再確認提交。既有 FinishRound 由伺服器累計勝場，達兩勝才定案、晉級及派彩；不能由樹任意指定整場勝者。現有契約定案不可逆，本輪不新增改判、退款或回滾 API。

## 真實資料界線

只有完整規則示範樹可由 slot/2 推導拓樸。正式公開 API 尚無完整下一場／席位欄位，因此僅接已確認且唯一出现在下一輪席位的勝者；未知、重複及衝突關係不猜線，顯示待公布提示。未來 API 提供關係後，可由展示層傳入 nextMatchId／nextSlot，不能手寫後端契約。

公開資料尚無裝備與玩家肖像，保持待公开與字印；不拿示範配裝當正式資料。不包含正式部署。

## 2026-09-21 示範管理與勝敗效果

頁面 `?preview=1` 且已有公開示範樹時，提供「進入編輯模式」「選場編輯」、黑白卡面互換、效果重播、復原及還原本階段示範。正式資料不載入編輯器。

編輯模式中點名帖、比分或冠軍卡開啟原生 dialog，可選場、調整比分／狀態／本場勝者。選勝者自動填入符合 BO3 的比分，輸入比分也會推導完成狀態；2:2、負值、小數、同人對打等不合法組合不能套用。

玩家由首輪交換籤位，避免同人重複出場。後輪選手由前場胜者帶入；更換贏家或交換首輪玩家會清除受影響的後續比分，季軍戰跟隨準決賽敗者。只改比分但贏家未變，不清除仍有效的後續賽果。空席／輪空不捏造比分。

localStorage 使用獨立 `lunjian.bracket-editor.v1.[phase]` key，保存操作紀錄及黑白偏好；按階段隔離。刷新可還原，損壞資料回到基礎示範並提示，儲存失敗時仍保留當次記憶體操作。提供復原上一步；還原示範須再按一次確認。不存通行碼／注單，不呼叫任何後端。

勝章與敗退只在結果身分改變或主動重播時播放，普通輪詢不重播。線條流動在非目前章節暫停；版面、觀察器、事件、dialog 與焦點均在卸載清理。

正式限制：既有 JudgeService 支援賽前 SwapSeeds 及逐回合 FinishRound，不支援任意改寫已結算比分／贏家。正式裁判台沿用原權限與確認流程；本機示範修改不等於正式管理端已提交。若需要正式改判，須擴充後端的稽核、晉級及派彩回滾契約，此輪不臆造 API。

來源新增 lab/bracket-editor.js/css，由首頁生成器同步；其他樹狀圖與 React 裁判正本關係不變。


## 2026-09-21 黑方與敗者辨識修正

黑白是陣營身分：黑方保留墨色素材，白方保留紙色素材；兩者都有獨立反差底色的方別標籤。落敗統一轉灰紙，使用可讀的深墨文字、暗紅「敗」印、虛線外框與局部邊角裂痕，不再用黑卡表示敗者。勝者維持大斜勝章。敗印與紙色轉換只在結果更新／手動重播時播放，靜態閱讀及 reduced-motion 停止動畫。

已確認勝者的晉級線由 2.5px 加粗為 4px，查看選手路線時為 5px 並維持亮黃色；流動筆觸同步加粗至 2px。未確認路線維持細線，不能以動畫捏造晉級。React 裁判樹同步使用此結果語彙。


## 2026-09-21 中央直線與容器響應式

決賽雙方名帖與冠軍保持同一水平中線，各自由水平線直接接到冠軍卡邊緣；只有實際勝者的一側高亮流動。比分仍是冠軍下方的獨立操作，不再充當晉級線節點，移除原本向下繞行與冠軍底部短線。早輪配對維持必要的直角分支。

樹寬改由容器與輪數計算，名帖在 112–144px 間調整，保留比分節點空間與捲軸安全留白；可用空間小於可讀完整樹時切換分輪（手機仍強制分輪），不縮放文字、不裁切兩側名帖。CSS 使用 runtime 的 data-view，裁判側欄也能一致適應。減少中央垂直留白；長姓名仍由實測高度避免重疊。視窗縮放保留焦點所在輪次，分輪標籤退出時焦點回到同輪場次。

## 2026-09-21 示範資料室、簡化編輯與冠軍特效

資料室提供 8/16/32/64 快捷鍵及 2–64 整數輸入，預覽比賽前／比賽中／完成。人數不足下一個二次冪時，首輪分配 size-count 位輪空，直接晉級且 0:0；待前場勝者的後輪席位不視為輪空。增加的玩家明示為示範俠客，沒有偽造正式資料或裝備。

各人數／進度獨立儲存操作，另保存目前選擇；原始人數與原始進度沿用既有 v1.phase key，切換後仍能找回既有比分。完整樹模式允許桌機圖內橫向捲動，分輪及自動模式仍可選；手機強制分輪保留可讀性。

原生 dialog 保留焦點與 Escape，簡化為場次、兩側玩家與大比分、此方獲勝快捷操作、狀態、結果摘要及單一儲存按鈕。點贏家自動帶入符合 BO3 的比分，錯誤留在表單內，後輪換人仍需修改前輪。

確認冠軍才有魁印、金框展開與人物淡入；全部只使用 transform／opacity，不新增套件或持續大面積發光。輪詢不重播，改冠軍或效果重播才重啟，非目前章節暫停；reduced-motion／靜態閱讀呈現完整靜態冠軍卡。


## 姓名與捲動精簡

姓名區只保留姓名，不展示段位、籤號或勝敗副列。勝敗改由既有印章／色面／路線表達，比分維持原位。tt-viewport 取消 max-height:76svh，使用 max-height:none、overflow-x:auto、overflow-y:hidden；內容高度由完整 canvas 撐開，y 軸允許 scroll chaining，上下只捲動外層章節／閱讀頁，避免巢狀垂直捲軸。


## 敗者斬切效果

已確認敗者使用 tt-cut-flash 刀光（96,0 → 4,100），約 240ms 後兩片 tt-cut-piece 沿相同鋸齒切線分離：上片左上移、下片右下移並轻微旋轉，留下裂口。刀光單次淡出，卡面保持撕裂結束姿態；姓名及比分只保留一份，不切斷文字，不新增互動目標。裝飾隱藏於讀屏且不攔截 pointer。

動畫由 data-result-enter 驅動，普通輪詢不重播；手動重播或結果身分改變才播放，改判勝者移除斬切。減少動態／靜態閱讀停動畫，直接展示撕裂卡面；非目前章節暫停。沒有新增動畫框架，沒有模糊或持續閃爍。


### 2026-09-21 檢視／編輯與報名者安排

保留已確認的紅藍名帖、勝敗斬切、金線與中央冠軍美術。工具列改為「檢視／編輯」；檢視僅留模式與排版選擇，編輯才顯示 2–64 人設定、報名者及比分工具。報名者可搜尋、新增，拖曳到首輪卡片或點選姓名後點籤位；另有目標籤位下拉選單，供手機／鍵盤操作。已排入者交換籤位，待排入者替換上場，被替換者留在報名者名單；人數不因換位增減。
