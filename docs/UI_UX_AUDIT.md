# 論劍 Theatron — UI／UX 設計審查

日期：2026-09-20。範圍：目前本機版本。下方保留修復前的診斷證據；使用者已核准全面修復，八項修正與重現步驟見 [UI_UX_VERIFICATION.md](UI_UX_VERIFICATION.md)。

追加需求：使用者明確取消第 04 項原先的「直接進入」提案。現行開場採 KAGE 式載入、全畫面點燃與幕後雙俠，實作及驗收見 [OPENING_DESIGN.md](OPENING_DESIGN.md)。下文原始審查仍作為歷史紀錄。

## 判斷

目前設計把大量注意力交給場景、題字、切鏡與氣氛，使用者完成任務需要的資訊與控制則偏弱。最需要反省的是設計順序：先安排一個漂亮鏡頭，再把功能放進剩餘空間，造成關鍵內容自動消失、導覽斷點缺口、按鈕文案與行為不符。應先建立穩定的閱讀與操作區，再讓武俠場景支援它。

保留論劍的夜色、墨字、朱印、戰帖和七格定格導覽；目前證據不支持整站換風格，也不需要恢復滾輪切格。

## 01 — 動畫不能把必讀內容拿走

**證據：** 手機賽制先顯示其中一步，停留後畫面只剩背景。DOM 實測 `.rule-table` computed opacity 為 `0`，三個 `.case-step` computed display 全為 `none`。同時 `.status-bar` 為 `display:none`，其內的「靜態閱讀」按鈕不可用。

**來源：** [lunjian-layout.html](../../scrollcraft/builds/lunjian/lab/lunjian-layout.html) 的 `DWELL = 11000` 與 `updateDeck()`；當 `S.frac >= .65`，程式主動把規則透明度設為零。按設計是章內計時約 7.15 秒開始退場；背景分頁的幀率節流可能延長牆鐘時間，本次沒有把它當精確效能量測。

**反省：**「留一段靜默讓人看景」用在讀取賽制的區域，等於設計替使用者決定閱讀時間。手機只輪流顯示一步又沒有回看控制，問題更嚴重。

**修改：** 保留背景呼吸與題字入場，正文不退場。三步預設完整可讀；若要逐步說明，加可點的上／下一步。閱讀模式在手機也應有入口，且切換後必須清除殘留的 inline opacity。

**驗收：** 375px、390px、桌機停留 30 秒、切走再返回，規則完整可讀；沒有視覺上已消失但仍存在報讀樹中的正文；不需重新整理找回內容。

## 02 — 按鈕必須說出下一步真的會發生什麼

**首頁證據：** `#register-cta` 顯示「報名參賽 ↗」，DOM 的 `href` 仍是 `#rules`。`renderRegister()` 更換狀態與按鈕文字，沒有同步更換 href。「比賽中」與「結束」分支也只改文字，因此來源顯示另外兩態同樣有目的地不符風險；本輪沒有把三態全部點選測完。

**配裝證據：** 報名面板叫「完成報名」。[loadout.js](../../scrollcraft/builds/lunjian/lab/loadout.js) 的 `goSignup()` 實際導向 `/t/{slug}/signup?arts=...`，再由 [SignupForm.tsx](../web/src/features/signup/SignupForm.tsx) 預填文字。它完成的是前往報名表，並非提交成功。

**修改：** 首頁按真實活動資料決定「尚未開放／報名參賽／查看賽程」及連結。配裝按鈕改「帶入配置並前往報名」，面板改「準備報名」，在真正提交成功後才用「報名完成」。賽事名稱應盡量由上下文帶入，不要讓一般選手猜 slug。

**驗收：** 每一態逐一核對按鈕文字、目的地、前置條件與成功回饋；後端不存在時不能以假開放狀態冒充完成流程。

## 03 — NAV 要反映任務，也要在所有寬度存在

**證據：**

- 1440px：七項都是 12px、同等視覺重量，僅用細底線標記目前章節；DOM 未設定 `aria-current`，只用 `data-here`。
- 960px：`body[data-device="desktop"]`，`.site-nav` 與 `.progress-rail` 都是 `display:none`。JS 的 mobile 門檻為 900px，而 CSS 在 1023px 以下先把 NAV 隱藏，產生 901–1023px 的細指標裝置缺口。
- 390px 報名章節：NAV 可視寬 343px、內容寬 405px、scrollLeft 為 0。「報名」的 x 約 363.5px，右緣約 421.5px，當前項目藏在可視範圍外。
- 首頁 NAV 全部是章節錨點，沒有現有 `/loadout` 工具的清楚入口；使用者知道的七個場景與實際功能之間缺一層連結。

**修改：** 保留章節故事線，另外讓主要任務「報名狀態／備戰方案／賽程」有明確入口。手機將主要操作留在橫向清單之外；切格時把當前章節帶進可視範圍，設定 `aria-current="location"`。不要用一條更長、更小的 NAV 補所有需求。

**驗收：** 375、390、768、900、960、1024、1440px 均有可見導覽；當前項目看得到；鍵盤與觸控均能抵達每章與主操作。定格模式若沒有頁面捲動，移除誤導性的微量整頁捲軸，保留內容區真正需要的捲動。

## 04 — 開場需要明白的邀請

**證據：** 本輪預設首頁曾呈現整幅旗幕與一圈擴散提示，品牌導覽被隱藏。來源 `#boot` 是只有裝飾 span 的 div；[stage3d.js](../../scrollcraft/builds/lunjian/lab/stage3d.js) 透過全域 pointerdown、Enter、空白鍵與 Escape 觸發進場，畫面本身沒有文字說明這些操作。

**反省：** 圓環同時像載入中與可點區域，首次訪客無法確定應等候還是操作。鍵盤程式支援不等於介面已告知可操作。

**修改：** 添一行低干擾提示「點擊旗面入場」，加「直接進入」語意按鈕及焦點樣式。場景未就緒時顯示真實載入狀態；準備好後再顯示入場提示。保留美術，但不隱藏通過門檻的方法。

**驗收：** 不看說明的首次使用者知道如何進站；Tab 能找到跳過入口；無 WebGL／減少動態仍可直達內容。

## 05 — 讓資訊量決定版面重量

**證據：** 報名前，「對決」大幅角色與 VS 只有待定；「獎賞」四個大紅印各配待公布；「賽程」四個日期待公布，大面板中央又是一張待公布紙卡。三個章節傳達近似狀態，卻要求三次導覽。

桌機底部「報名前／進行中／頒獎」視覺像產品操作；只有群組的無障礙名稱說它是示範。`setPhase()` 取自 FIXTURES，示範標籤主要位於賽程面板，其他章節未同樣清楚傳達資料性質。

**修改：** 報名前優先呈現活動是什麼、誰能參加、核心賽制、何時與如何報名。日期未定就用精簡公告，不用空表格與大容器放大缺資料感；獎項尚未定可收成摘要。預覽切換留給明確標示的預覽工具，訪客看到的是活動狀態。

**驗收：** 第一屏能回答活動類型與下一步；每個主要章節都有獨立、可用的內容；不捏造日期、獎金、主辦與聯絡資訊。

## 06 — 功能文字要有自己的閱讀條件

**證據：** 首頁桌機 NAV 12px；配裝心法、奇術、裝備、戰力等區塊標題 computed font-size 為 11.5px，而裝備倉庫標題為 25px。小標與正文的重量不一致，倉庫在空資料時仍成為最強文字焦點。首頁報名區的淺色樹枝穿過按鈕與主辦文字；賽制小字直接落在高細節屋簷與雪景上。

**修改提案：** 功能導覽先以 14–16px、主要內文 16px 附近、輔助字 12–14px 試排；這是本案起始建議，不是合規結論。讓章節標題、操作標籤與資料讀值各有固定角色。內容區以現有深色材料建立局部閱讀底，或移開前景，不靠更重陰影硬救文字。

**驗收：** 真實背景與動態各幀不遮蓋關鍵字；桌機／手機能快速掃出主操作；以實際合成後畫面量測文字對比。這輪沒有宣稱整站通過或不通過 WCAG 對比測試。

## 07 — 減少爭奪注意力的物件

**證據：**

- 2D 山門同時有背景左上暗月與題字旁亮月；亮月緊靠主標，搶過較小的活動資訊。
- 戰帖同時有左側大型墨字、紙卡「戰帖」、紙卡英文字標、標題下另一段英文；同一分類被重複標記。
- 獎賞四個等大的紅印先被看見，真正說明縮在下方；尚未公布的內容沒有支撐這種強調。
- 390px 報名的墨字在上方，主標與 CTA 在下方，中間大段空景，題字與操作像兩個獨立畫面。

**修改：** 先拿掉同角色的重複物件與標籤；戰帖保留一個章節標示，紙卡專注邀請內容。保留單一月亮與一個主要書法焦點。手機把章標、正文與 CTA 收成相連的閱讀群組；桌機允許左右敘事，但內容基準線與間距應一致。

**驗收：** 每屏能指出唯一主焦點與主操作；裝飾不佔正文安全區；刪掉的元素不造成資訊損失。不用增加更多卡片、光暈或動畫補空間。

## 08 — 配裝從第一個動作開始設計

**證據：** `#bhead` 的 DOM 為 `section`，沒有 role／tabindex；`renderBuild()` 只掛 `onclick = openBuildPicker`。它看起來像標題加說明，卻承擔最重要的「選流派」操作，無障礙樹也未把它列為按鈕。

初始桌機同時顯示四個心法空位、四個奇術空位、裝備格、空倉庫與空雷達。畫面呈現了完整資料結構，但還沒替新使用者安排第一步。上方「複製配置」已用強調色，當下卻尚無配置可複製。

**修改：** 在原有配裝區給明確「選擇流派」按鈕。空倉庫保留「新增裝備」，排序／篩選在沒有資料時降低重量。空雷達換成「完成配置後顯示比較」的短提示，沒有配置時弱化匯出與複製。讓「角色 → 流派 → 裝備／武學 → 檢查 → 前往報名」在視覺上可追蹤；熟悉使用者仍保留直接編輯效率，不強迫長篇教學。

另外在角色／儲存位置顯示「儲存在此瀏覽器」與備份入口。文字交接是 `?arts=` 預填，不是完整方案的伺服器同步，介面應說清楚。

**驗收：** 只用 Tab、Enter 能開始選流派；初次進入可辨識第一步；空狀態的比較圖不暗示有效數據；手機可在配置、倉庫、檢查之間往返而不丟資料。
