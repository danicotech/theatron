# 2026-10-22 宗旨與共用動畫效能改善

## 範圍與量測方法
以實際使用中的章節 runtime、共用水波及 3D 場景為範圍；未使用的舊展示元件不另行重寫。以同一內建瀏覽器、1280×720、`?intro=0&stage=2d|3d&perf=1#prologue` 比較進頁後 10 秒的 rAF 間隔與 Long Tasks。診斷僅明確帶 `perf=1` 才啟用，10 秒後停止，不對外傳輸資料。

基準：2D 最長幀 187ms／長任務總和 270ms；3D 最長幀 1656ms／長任務總和 3355ms。暖快取下有 64 個已載入圖片節點，不等於 64 次下載，也不能據此宣稱已解碼；保留這項限制。

## 已實作
1. 切頁墨紋的 noise/field 計算移至 module Worker，傳回可移轉的 typed arrays。尺寸版本過期不採用，離頁 terminate。Worker 不可用時保留 CSS 切頁，不同步生成重型 field。
2. 非目前章節與背景 shot 使用 display:none，停止不可見內容繪製並讓原生 lazy loading 生效；靜態閱讀保留全部章節。下一章仍先準備圖片再揭幕。
3. 共用場景迴圈限 30fps、頁籤隱藏時取消；視差變數只寫入場景與前景節點，數值未變不寫。移除逐幀重設規則步驟樣式，跳過隱藏的舊 wordmark 動畫。
4. 3D 建築、地形、樹木按區塊讓出主執行緒；材質與 shader 分別預備。頂點焊接採原 Three.js 演算法，在大網格迴圈中分段讓出時間，索引／屬性／morph 資料保持一致。
5. 匾額 GLB 從巨型 JavaScript base64 移為同站二進位資源，避免主執行緒逐字解碼。沒有播放開場時跳過布幕 prepare 與首次布幕繪製；靜態閱讀不建立或繼續繪製 3D。
6. 按鈕水波改作用於完整控制項，使用同一水面法線折射底色、文字及圖示；不再由填色遮罩裁切。貼圖上限 180×90、更新最高 30fps，離開／失焦回收 filter，保持原節點和點擊行為。

3D 效能修改使用 lab/jz/js 的明確維護快照及生成器同步，不覆寫整個凍結引擎；這是本次使用者要求整體效能改善所需的有限擴充。

## 驗證與限制
- 133 項章節、漫畫順序、題字、開場、水波回歸通過。
- 真實 Three.js BoxGeometry、SphereGeometry（含 morph）與原頂點焊接結果一致；大網格讓事件迴圈執行 7 次。
- 桌機實際切換宗旨→規則→宗旨，內容正常；390px 宗旨無水平溢出。
- 3D 首次 GPU shader／繪製仍有驅動端成本；本次不宣稱所有裝置穩定 60fps。長期若要進一步降低首次載入停頓，應把靜態建築預先烘焙成壓縮模型並依視距載入，再針對實機 GPU 量測。
- 最終量測、建置及發布記錄於 DEVELOPMENT_PLAN.md 與 flow-audit。
