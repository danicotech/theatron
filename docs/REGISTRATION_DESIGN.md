# 報名設計與流程（2026-09-30）

使用者最新要求取代先前中央卷軸設計：報名使用與配裝、規則正文相同的紙頁語彙，停止使用捲軸、軸頭、拉籤與收卷動畫。

## 元件與一致性

| 元件 | 規範 |
| --- | --- |
| 報名入口 | 紙頁、單一標題、流程提示、一個依活動狀態變更的主要入口 |
| 表單容器 | 語意 paper token；標題 28–36px、內文 16px；返回為一般次要按鈕 |
| 流程導覽 | 沿用 Participation 四步狀態；桌機四欄，手機兩欄；當前步驟朱紅底線，未到步驟禁用 |
| 資料欄位 | 使用同一表單邊框、留白與錯誤訊息，不再有卷軸專屬底線欄位 |
| 身分與配裝 | 沿用既有會員登入、已存角色與配裝交接，避免複製另一份流程 |
| 送出與回執 | 沿用驗證、確認送出與已完成報名狀態；進度改變不代表已送出 |

## 使用者流程

1. 報名章 → 查看流程與活動狀態 → 開始報名。
2. 了解說明 → 登入／註冊 → 填寫報名 → 設定角色 → 確認送出。
3. 返回入口時保持表單掛載，保留未送出內容；再次進入回到原進度。
4. 已排名單的活動顯示「查看參賽資訊」及不開放新增報名的提示；不得呈現管理者建立活動的操作說明。
5. 配裝返回報名沿用活動與會員檢核；名額、報名截止、資料驗證仍由原業務元件處理。

## 維護邊界

RegistrationScroll 的檔名暫保留供既有掛載引用，實作已是一般 Registration panel；不再含動畫計時器或幾何探針。Participation 是首頁與觀局共用表單，避免分岔資料與驗證。首頁來源為 lab，透過生成器同步。

## 驗證

1198px 與 375px 瀏覽器確認入口文字、版型、表單、返回焦點、重入草稿及無水平溢出。Bridge/labRuntime 39 項通過；typecheck、ESLint、token 檢查通過。截圖見 previews/september-polish/registration-entry-* 與 registration-form-*。本次僅驗證 2D 場景。
