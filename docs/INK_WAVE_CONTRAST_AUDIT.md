# 全站水波互動文字對比修正（2026-10-28）

## 原因與修正

水波複製按鈕內容並將文字反色，但複製的 BuildCard、標籤與說明仍帶著原本底色。明亮模式形成深底黑字；暗色模式形成淺底白字。只把最外層 color 改成 inherit 無法處理多層 CSS Module 的背景和字色。

共用 ink-wave.css 現在讓遮罩內的複製內容使用同一組水波底色／文字色，清除內層背景圖、底色與陰影，不改變排版和字級。完全填滿時套用相同規則至原內容；水波退去時恢復原始元件樣式。原生事件、焦點與唯一可存取內容保持不變。

主要操作及選取狀態改用成對 accent-action-primary／text-on-action，避免局部主題底色與全站強調色交叉繼承造成低對比。其他變體沿用既有語意色。

## 影響範圍

| 共用入口／類型 | 處理 |
| --- | --- |
| button、summary、區塊連結 | 共用修正，自動涵蓋動態掛載元件 |
| SelectedLoadout 角色方案、CharacterArsenal 流派選擇、SavedLoadoutRoles | 內含 BuildCard 的空狀態與文字卡片採一致反色 |
| MyPlayer、LoadoutPreview、報名確認、管理名冊等 BuildCard 使用點 | 靜態展示維持原配色；位於可互動父元件內才套用水波規則 |
| 導覽、章節匾額、讓武分類、收合標題、賽程文字操作、登入操作 | 同時檢查文字、標籤、說明與選取狀態 |
| primary、secondary、money、danger、selected | 明／暗、1247／390px 逐項檢查 |
| 人物圖片、關閉、品牌及專屬導覽圖示 | 保留既有排除規則與各自互動，不強制加水波 |

## 驗證與限制

- Chromium 掃描首頁、七章、配裝、元件展示及登入，共 11 個路徑，兩種寬度、兩種明暗模式，加上 24 個巢狀卡片變體案例。
- 本機合計 656 個控制項／狀態、1060 組文字樣本；計算對比全部 ≥ 4.5:1，最低 6.86:1。這是測試矩陣數量，並非 656 種獨立元件。
- 截圖重現的卡片由約 1.12／1.16:1 提高為 14.32／14.18:1。
- 一般動畫測試包含部分填滿、完全填滿、滑出還原、鍵盤焦點、實際 touchStart／touchEnd 和動畫中換主題；兩種尺寸、明暗四組皆通過。觸控仍可點擊，無常駐遮罩。
- 角色方案以實際 BuildCard／SelectedLoadout CSS 和相同巢狀結構在隔離頁注入測試，未使用使用者登入資料，未提交表單。需登入的所有後台畫面未逐一實機操作。
- 對比為計算後文字色與不透明水波面的 WCAG 比值；不是對折射高光每一幀的像素取樣。另檢視動畫中途與完成截圖。

## 重跑與防止復發

使用已有 Playwright 的環境，不需更改產品依賴。可透過 PLAYWRIGHT_MODULE 指定其模組 URL；PLAYWRIGHT_BROWSERS_PATH 指向已安裝瀏覽器。AUDIT_URL 預設 http://localhost:3014；ARTIFACT_DIR 可指定報告／截圖目錄，預設寫入系統暫存。

```sh
node scripts/browser/ink-wave-global.mjs
node scripts/browser/ink-wave-motion.mjs
```

新卡片有內層底色時，要檢查整個互動面的文字／背景配對，不能只改最外層 color。驗收至少包含明暗、部分／完整水波、還原、鍵盤與觸控；不能只驗靜態未 hover 截圖。裝飾層維持 aria-hidden／inert，不複製成第二個可操作元件。
