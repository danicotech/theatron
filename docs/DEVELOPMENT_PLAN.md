## 工作順序

### A. 本輪已完成：可檢視的開發起點

- 啟動本機前端並檢查主要頁面與主要 CSS／JS 回應。
- 建立工作區路由與 Theatron `AGENTS.md`。
- 建立 [技能對應](SKILL_MAP.md) 與 [啟動手冊](DEV_SERVER.md)。
- 記錄首頁／配裝的唯一來源、既有修改與後端限制。

### B. 下一輪：按使用者需求修改指定畫面

每輪處理一個明確需求，例如首頁某格、配裝流程、報名表或賽程呈現。先確認目前畫面及源檔，再產出簡短規格、修改、必要生成與驗證。不預先決定新的配色、字體、版面或套用全站效果。

### C. 使用者需要完整流程時：後端串接驗證

確認 Hestia 開發環境、真實活動 slug、允許使用的測試帳號與契約版本。先驗證讀取與登入，再按需求驗證報名、讓武、投注及裁判流程。配裝已有文字預填交接；整包方案的後端儲存需另行定義，不能把 localStorage 當後端紀錄。

### D. 交付前：針對實際變更驗收

檢查桌機與手機、鍵盤、loading／empty／error、reduced-motion、資源載入及相關測試。動效或 3D 有修改才做對應效能量測。部署與外部發布等使用者要求時再處理。

## 每次需求記錄格式

| 欄位 | 要記什麼 |
| --- | --- |
| 目標 | 使用者要達成的操作或看到的資訊 |
| 路由／區段 | 精確到頁面、章節或元件 |
| 修改來源 | 原始檔、生成器、輸出檔 |
| 內容與層級 | 主標題、說明、主要動作及使用者提供的文案 |
| 保留條件 | 現有風格、資料、互動、響應式要求 |
| 適用 skills | 依 SKILL_MAP 挑選並讀取原文 |
| 驗收 | 可觀察的通過條件、操作步驟、相關測試 |
| 結果 | 已完成、待辦、依賴與實際驗證證據 |

資訊可由程式或使用者上下文推知時直接推進，只有會影響方向或結果的缺口才詢問。

## 持續保留的決策

1. 論劍現有視覺與定格導覽是基線；通用設計／捲動技能不能覆蓋它。
2. 首頁與配裝先改 lab，再生成；React 路由與掛載問題才改對應整合層。
3. 共用展示元件不耦合業務；契約由 proto 生成；金額保留精度。
4. 本輪不清理既有未提交修改，不重建已存在的功能，不把後端未驗證寫成已完成。
5. 技能按需求套用，新增套件與架構改動需有具體用途。
