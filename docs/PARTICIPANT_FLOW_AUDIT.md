# 報名者流程驗收與修復

日期：2026-10-12。角色：報名者。使用獨立 Playwright browser context；每個尺寸建立自己的會員與活動，未連接或改動使用者瀏覽器現有資料。

## 範圍與設計依據

沿用 design-taste-frontend 的既有網站定向修正原則。多步表單及賽事操作使用專案 tournament-design-system；保持原本紙墨介面、語意 token、44px 操作目標及手機排版，未重畫首頁或更换動畫框架。

## 發現及修复

1. 登入後的報名表依會員 ID 重掛，導致剛勾選的已讀確認遺失。新增只在報名登入成功時交接的 event/user 同意狀態。取消登入不交接；帳號切換仍保留元件隔離。
2. 本機試玩原本沒有實際 BP 購買資料，只有示範文字。新增獨立本場讓武面板、正式 36 項目錄、評段／選購／移除／裁判退款命令。
3. BP 僅由大會明確評段決定，不能將報名自評當成已核准段位。每差一段 8 BP，低段方才能選購；對手未定或未評段顯示等待。
4. 指定型項目須填內容，可重複項逐筆指定，不能重複相同內容或超出預算。開局台詞驗證 8 字（不計標點）。開賽鎖定三局配置，不能再選購、移除、退款或直接修改已使用段位。
5. 高段方開賽前不公開對手選購內容，鎖定後公開；管理者能預先檢視。裁判退款要求原因、返還本場 BP 並保留紀錄，不改會員點數。原文要求裁判確認的退款不自行推測；可以拒絕的要求保留原條文。
6. 讓武操作在儲存中只停用按鈕，不卸載目錄，保留展開分類與焦點。重新排籤清空本場讓武選擇，保留已評段位。

## 實測路徑

腳本：`scripts/verify-participant-role-browser.mjs`。

- `/home` 點「提筆報名」，已讀卡片空白區可勾選。
- 完成本機註冊，已讀狀態保留；填遊戲 ID、公開角色名、對戰經驗與時段。
- 前往我的武學配置，選鳴金虹流派，倉庫新增裝備、掛到主武器、保存角色。
- 帶回原活動及報名第三步；原私人欄位、角色名稱及配置仍在；確認報名後重新整理仍顯示完成。
- 另以 UI 建立三位會員並完成報名，共四位。管理者關閉報名、確認發布對局。
- 管理者將同場雙方評定為無我／開山；低段會員從「我的參賽」開自己的對局，選禁用任意奇術「太白醉月」，扣 3 BP 後剩 21/24。
- 本人場次的下注按鈕停用；切另一場可選勝負，確認 100 點下注，會員餘額由 1,000 變 900。
- 管理者填退款原因並退還 3 BP，保留退款紀錄；開始本人場次並封盤後，參賽者只能讀鎖定讓武內容。

每次截圖檢查 document 橫向溢出，並收集 pageerror。實測使用 2D／reduced-motion 支援路徑，不代表 3D 效能驗收。

證據：`docs/previews/participant-role-audit/results.json`、同目錄 `entry`、`equipment`、`role-return`、`receipt`、`published`、`bp-selected`、`other-match-bet`、`bp-locked` 截圖。

## 程式回歸

- `bp.test.ts`：正式 36 項名稱／價格／描述一致性，未評段、8BP預算、身分限制、重複指定、超額、開賽鎖定、退款紀錄、重新配對、8字台詞。
- `ParticipantBp.test.tsx`：指定內容提交、對手開賽前保密與開賽後公開、觀眾不顯示讓武面板。
- `Sportsbook.test.tsx`：既有投注與報名回歸。

## 真實限制

這次完整操作的是 IndexedDB 本機試玩系統，不是正式線上服務。本機管理模式不是正式管理權限；跨裝置帳號／交易、正式裁判權限與 Hestia RPC 未驗證。本次沒有後端位址或憑證，不應宣稱正式報名、正式下注或遠端多人同步已上線。

BP 目錄保留正式條文，不會自動操作遊戲按鍵、血量、勝負或先後手。執行方式與可拒絕／退款爭議仍由裁判確認。

## 最終結果

1198px 與 375px 全路徑均通過（各有四個實際由 UI 註冊及完成報名的隔離會員），兩者 `errors: []`，所有記錄截圖均無 document 水平溢出。手機下注先使用底部「查看注單」操作，再輸入本金及確認扣點。38 項相關測試通過、相關 ESLint 通過、typecheck 通過、364 檔語意 token 檢查通過。其他 agent 後續共用變更由主 agent 最後統一回歸。
