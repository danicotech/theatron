# 即時賽事與雙人對局工具：環境移轉交接規格

更新：2026-10-12。狀態：**需求與接入位置已保留，尚未串接或驗證跨裝置同步**。

使用者已確認後端存在，將轉換環境後再開發。本輪不建立替代後端、不猜測服務位址、不修改生成契約，也不把本機試玩升級成正式多人服務。

## 不可退回的產品原則

1. 正式賽事的已提交變更，須即時傳給有權查看的其他玩家、觀眾與裁判。操作方看見成功，不代表其他人已同步；兩者都要驗收。
2. 同步由後端權威狀態驅動。前端動畫不決定骰子點數、勝負、賽果、扣點或派彩；本機 BroadcastChannel 不是跨裝置同步。
3. 小工具由「裁判指定兩名玩家」或「玩家選擇對手並邀請」建立房間，不能讓一個人代替雙方完成出拳。
4. 小工具永遠不自動更動先攻／後守、BP、籤位、場次比分、勝者、下注或賽事階段。正式設定仍由原本授權流程獨立確認。
5. 即時可見不代表全部公開：未揭曉出拳、未公開 BP、私人報名資料、個人餘額與注單依權限同步，不得先廣播再用 CSS 隱藏。

## 現況與既有契約

| 位置 | 已有實作 | 本次要求的差距 |
| --- | --- | --- |
| `web/src/lib/api/activity.ts` | `activityApi.watch` 綁定生成的 WatchService | 尚無實際訂閱消費端 |
| `web/src/lib/api/gen/hestia/activity/v1/watch_pb.ts` | WatchTournament：match、handicapLocked、odds、phase、champion、heartbeat | 尚無雙人房間、完整名單／籤位變更及其他新增領域通知 |
| `web/src/lib/api/poll.ts` | usePolling | 現行輪詢是待遷移實作，不是最終即時方案 |
| `web/src/app/LunjianRuntime.tsx` | 正式 API 狀態投影；賽程定時重讀 | 要接同一活動訂閱與重新同步生命週期 |
| `web/src/features/sportsbook/database.ts` | IndexedDB + BroadcastChannel | 僅同源本機分頁；不具備正式權限或跨裝置能力 |
| `web/src/features/sportsbook/MatchTools.tsx` | 單機骰子、共用裝置猜拳 | 沒有真實玩家選擇、邀請、房間與後端結果 |

既有 WatchService 是 **ConnectRPC server streaming**，不是 WebSocket。使用者允許「WebSocket 等方式」，優先延續此契約；是否需要額外傳輸協定要在新環境依後端決定，不先建立第二套事件格式。

命令仍用生成的 unary RPC；推播用生成的 streaming RPC。契約正本在兄弟專案 `hestia/proto/`，修改後執行 `pnpm gen:api`。此文件的名稱是需求描述，**不是已存在的 RPC 或手寫 request/response 型別**。

## 雙人房間流程

### 裁判指定

- 在活動裁判頁開啟「對局小工具」，從該活動可用玩家名單選甲、乙兩人；可由目前場次預填，但必須確認，不能以顯示名稱作身分。
- 選擇「擲骰比大小」或「剪刀石頭布」，送出後由後端驗證裁判權限與玩家資格。
- 兩名玩家各自收到房間通知，進入後確認準備；裁判看到接受、準備及離線狀態。裁判不能代出拳或指定結果。
- 玩家拒絕、房間取消或逾時均產生可同步狀態，不算任一方輸。

### 玩家邀請

- 已登入玩家在活動內選擇對手；自己為固定一方，不可邀請自己或冒用第三人。
- 對手收到邀請後可接受／拒絕；邀請者可在開始前取消。後端限制未結邀請、重複邀請與頻率，防止洗版。
- 接受後兩人確認準備，房間進入本回合；裁判可按權限查看及取消，但不得覆寫任何人的選擇。
- 玩家斷線後保留房間和已提交內容；重連重新取得快照。逾時為過期／未完成，不以斷線自動判敗。

### 回合狀態與比大小

房間：邀請中 → 雙方加入 → 準備中 → 回合進行 → 已揭曉；另有已拒絕、已取消、已過期。

- 每次重賽建立新的回合代號，雙方重新準備；舊回合結果保留，不可在同一回合覆蓋重擲。
- 骰子預設每人一顆六面骰，點數較大者勝，平手可重賽。雙方各自按擲骰，由後端 CSPRNG 產生並保存該方唯一結果；兩方完成前只公開「已擲骰」。
- 猜拳由本人送出選擇，伺服器保存後只回報已出拳；本人不能撤回或更換，任何其他用戶（含裁判）在揭曉前均收不到內容。
- 雙方完成後，後端在同一筆回合結算中保存兩方結果與勝負，再推播揭曉。重試及重複點擊不再次產生點數或改變選擇。
- 動畫使用伺服器的回合階段、開始／揭曉時間與已保存結果；前端不得用 random 或本機倒數先行宣布勝者。晚加入／重連直接顯示當前狀態，不重播舊回合。
- 裁判與兩名玩家可查看房間。公開觀戰須由裁判明確開啟；僅揭露允許公開的身分、狀態與已揭曉結果。
- 這是信任裁判服務的工具；若之後要求「連服務端都不能預知出拳」，需另外評估 commit–reveal，不宣稱此規格已提供可驗證公平性。

## 所有改動的同步範圍

表中「公開」均指後端已核准公開的資料；未按送出、尚未套用的拖曳草稿與文字輸入不廣播。

| 已提交變更 | 公開觀眾／其他玩家 | 本人／裁判專用 |
| --- | --- | --- |
| 活動名稱、規則版本、階段、報名開關 | 更新活動與 CTA；規則版本改動須重新確認已讀 | 本人已讀版本及需要補確認的狀態 |
| 報名、配裝、退賽、評段 | 已公布的名單、角色配置與段位；未公開時僅允許的統計 | 報名草稿、聯絡資訊、審核狀態 |
| 抽籤、換位、套用籤位、輪空 | 一次更新完整籤位與對陣關係 | 未套用的編輯草稿僅裁判本人 |
| BP 選購、移除、退款、鎖定 | 封盤後的完整公開清單及其更新 | 封盤前僅購買者與授權裁判；本人預算同步 |
| 開賽、回合開始／結束、時長、賽果、晉級 | 賽程、場次、比分、伺服器時間與名次 | 合法裁判操作及審核紀錄 |
| 盤口名稱、類型、開关、賠率、票數 | 更新所有相關盤口與舊注單草稿的可提交狀態 | 本人投票狀態不能被匿名廣播覆蓋 |
| 下注、取消（如業務允許）、結算、退款 | 僅公開統計與盤口狀態 | 本人注單、餘額、流水；授權管理查核 |
| 抽獎開始／結果、獎項與頒發 | 已公布的抽獎進度、得主、獎項及公開頒發狀態 | 配送／聯絡資料與私人通知 |
| 雙人房間邀請、接受、準備、提交、揭曉 | 僅已開放觀戰的房間公開投影 | 邀請通知與未公開房間；未揭曉選擇只在伺服器保存 |

新加的賽事寫入功能必須同時定義：接收者、公開時機、權威讀取 API、事件、重連快照、權限及測試。不能只讓操作方刷新成功。

## 後端契約待辦

- **已存在**：WatchTournament 匿名公開流，每屆訂閱一次；初次立即 heartbeat；重連不補送歷史、改讀現在快照。沿用現有語意，不將私人欄位加到匿名流。
- **待核對／擴充**：報名與公開名單、籤位、規則、盤口管理、BP 公開後退款、抽獎及頒獎的更新事件，不能假設既有五種業務事件涵蓋全部寫入。
- **待新增**：工具房間建立、查詢、邀請接受／拒絕／取消、準備、擲骰、出拳、重賽、逾時與訂閱；以真實活動／玩家 public ID 關聯，不沿用試玩 UUID 或輸入名稱作授權。
- **待核對／擴充**：本人通知／餘額／注單／報名／BP 的授權流或其他即時通知途徑。既有平台 notification 契約使用拉取確認，不得誤稱已經串流化。
- 房間、回合與賽事實體須有可比較版本，命令帶預期版本和冪等鍵；伺服器從 session 判斷 actor，不信任前端送來的裁判旗標或 userId。
- 公開流序號與私人流序號須依各自可見範圍定義，不能因隱藏事件而讓觀眾誤判缺包。快照需要一致性水位；既有 emittedAt 不能單獨證明多來源快照的新舊順序。
- 寫入、版本遞增、outbox 在資料庫交易中一起提交，成功後發布；多實例共用可靠事件來源，不靠單一程序記憶體廣播。下注／抽獎／回合結算的重送不得重複扣點、扣庫存或重擲。
- 確認賽事改判等原本不存在的寫入 API；即時推播本身不新增業務權限或允許任意改判。

## 前端接入位置與一致性

預留目錄：`web/src/features/realtime/`、`web/src/features/match-tools/`。目前只有接入說明，不是假裝可用的網路 adapter。

1. 以活動 slug 共用一份訂閱控制器與狀態庫，頁首、首頁舞台、賽程、裁判頁與投注元件使用同一來源；元件不得各開一條活動流。工具房間及私人流另依可見範圍訂閱。
2. 先建立 WatchTournament，收到第一則 heartbeat 確認訂閱成立後，再讀活動／賽程／盤口的權威快照；快照期間緩存事件，依版本／水位合併，避免較舊 HTTP 回應覆蓋推播。
3. 既有契約未提供完整水位前，不以 emittedAt 猜測快照版本；先完成後端契約設計。可採合併重讀／失效通知的過渡策略，但需驗證沒有掉更新及查詢風暴。
4. 斷線標示「連線中斷，正在重新同步」，保留最後畫面但標記過期；關鍵寫入暫停，不將離線操作排隊後偷偷送出。重連成功先快照補齊，才恢復可操作。
5. 重連使用有上限、帶抖動的退避；心跳逾時重建連線，回到前景立即重同步。切換活動、登出、session 改變和卸載時取消請求、流與計時器，清除私人狀態。
6. 套用重複事件無副作用；丟棄舊版本；發現缺口重新抓快照；未知必要事件觸發重新同步／版本提示，不能靜默漏掉功能。
7. 畫面狀態包含連線中、同步中、已同步、重連中、無權限及錯誤；連線成功但快照尚未套用時不能顯示「已同步」。低頻 aria-live 狀態通知不逐秒朗讀倒數。
8. 盤口更新保留私人 myVote；賠率改動要求重新確認；已封盤不能提交舊草稿。伺服器仍須在提交交易時再次檢查權限與狀態。

## 切換環境後的執行順序

1. 定位既有 Hestia，讀其 AGENTS／proto／schema／測試；核對生成檔與後端版本，取得允許測試的裁判、玩家、觀眾帳號與活動 slug。
2. 設定本機 HESTIA_URL，驗證同源 cookie、既有 unary RPC 與 WatchTournament 第一則 heartbeat。正式 ingress／反向代理需確認串流不緩衝、心跳與 timeout，不能僅以 HTTP 200 判定可用。
3. 先完成既有賽事流的前端接入與斷線恢復，再補齊缺少的事件和私人訂閱。
4. 在後端增加房間／回合持久化、授權、冪等與逾時，從 proto 生成 client 後實作房間前端與兩種選人入口。
5. 以獨立瀏覽器 contexts 及至少兩台裝置走下列验收；通過後再宣告正式多人同步可用。

## 驗收清單（待新環境執行）

- [ ] 裁判、甲、乙、觀眾四個獨立 session；管理修改後其他畫面不用重整。正常測試網路下，以提交成功至可見更新 p95 ≤ 1 秒為目標，記錄實測分布，不宣稱全球延遲保證。
- [ ] 裁判選人、玩家邀請、接受／拒絕／取消／過期；選自己、跨活動、冒名、非裁判操作及頻率超限被後端拒絕。
- [ ] 骰子／猜拳由兩台裝置提交，一回合只結算一次；揭曉前擷取網路訊息確認沒有對手選擇或点數，不能只檢查 DOM 隱藏。
- [ ] 重複點擊、HTTP 重試、相同冪等鍵、同時出拳、取消與提交競爭不重擲、不覆蓋、不重複產生結果；重新比試須雙方確認。
- [ ] 工具操作前後比較正式場次、先後攻、BP、下注与賽果均未改動；只有工具房間紀錄改變。
- [ ] 報名／配置、評段／籤位、BP、回合／結果、盤口、下注結算、抽獎／頒獎逐項驗證接收者和公開時機；保護私人資料。
- [ ] 網路中斷、重連、頁面重整、伺服器重啟、切換活動、登出再登入，不丟結果、不閃回舊比分、不洩漏前一帳號資料。
- [ ] 快照與推播競爭、重複／亂序事件、缺包、未知事件、大量變更與多伺服器實例一致性。
- [ ] 桌機／手機、鍵盤、reduced-motion；晚加入與背景分頁回前景顯示正確狀態，卸載後無殘留連線與 timer。
